# 两件装备制作与技能验证

2026-10-16。使用 `game-art-production` 与内置 ImageGen，分别制作已有强化装备“潜水护衣”和“精校枪机”的外观。沿用既有属性、强化费用、库存ID和存档结构。

## 来源与交付

- `diving-coat-generated.png`：以当前黄色雨衣层为编辑目标，生成防水加固护衣。黄色主体、深蓝绿护肩、黄铜铆钉与加固带。一次调用。
- `brass-revolver-generated.png`：以 `public/assets/game/items.png` 为画风参考，生成黄铜、暗钢与胡桃木握柄的精校枪机图标。一次调用。
- 完整提示词位于 `prompts.txt`。两张原始输出分别来自内置工具的 `exec-f248fa65-7ddf-4fac-899b-d809edda1f41.png` 和 `exec-83420a70-6a7e-4299-9620-449d6fdc9c6f.png`；原始文件保留，此目录保存副本。
- 运行资源为 `public/assets/equipment/diving-coat-layer.png`、`diving-coat-icon.png`、`brass-revolver-icon.png`。

`prepare.py` 记录固定坐标处理与导出。护衣原稿尺寸保持1024×1536，但按 alpha≥128 比较，仍有 29667 个轮廓像素与原雨衣不同。因此没有直接接入原稿，也没有继续重生成。处理时复用已验收的雨衣透明轮廓，锁定领口、双袖口、帽子与内衬遮挡区域，只在衣料内部叠加新细节。人物底图、握帽前景及运行时坐标均保持原有文件与规则。

第一次蒙版保护范围过宽，切掉了部分护肩。查看穿戴预览后，将保护范围收窄到领口实际区域；重新检查护肩连续性和接点。没有把自动像素检查当成视觉验收。护衣库存图标改用完整生成护衣，避免半身裁切造成衣摆截断。

护衣层与原层的全部 alpha 字节相同；保护区域的全部 RGBA 字节相同。检测记录见 `verification.json`，编辑区域见 `cloth-edit-mask.png`。这些证明坐标与指定接点保留，不证明所有美术细节自然；完整穿戴图与实际运行截图另外人工查看。

护衣库存图标清除淡透明边缘后裁去留白；枪械图标按 alpha>32 的内容边界裁切。没有缩放。素材编辑与裁切先完成，然后单独执行无损压缩，不能把裁切或 alpha 编辑称为无损压缩。

## 无损压缩

使用 Pillow 12.3.0，PNG `optimize=True, compress_level=9`。压缩前候选图和运行图的尺寸、全部 RGBA 字节均验证一致，仅采用更小结果。

- `diving-coat-layer`：480367 → 445249 字节，1024×1536。
- `diving-coat-icon`：731951 → 676438 字节，640×912。
- `brass-revolver-icon`：955611 → 902317 字节，1211×867。

## 技能验证结论

本轮使用的技能文件 SHA-256：`718ceb20499f0f8913e3de66c933681998a4cf11b438aaa18c12179eaff52a58`。验证期间没有修改技能规则。

本轮证据支持：修订后的流程能拦住未经几何验收的原稿，并用固定坐标和局部蒙版完成服装变体，而非反复整图生成或用CSS拉伸贴合。两件装备各一次生成，护衣仍需确定性后处理和一次蒙版范围修正。因此结论是制作与验收流程有效，不是生成器能够一次精确输出。

本样本复用了已有衣服轮廓与姿势，没有验证全新轮廓、全新动作或其他身体接点的服装，也不能据此保证后续所有装备一次通过。
