# 游戏技能共用约定

项目技能位于 `.agents/skills/`。从仓库根目录执行命令；技能内的相对链接按技能文件位置解析。

## 需求与证据

1. 读取 `AGENTS.md`、`docs/agents/domain.md` 和 `docs/design/game-design.md`，再读取本次涉及的专项文档。术语表和 ADR 不存在时继续工作。
2. 区分用户已确认要求、待审计建议、代码已实现行为。用户当前明确要求决定本次范围；文档中的历史“本轮仅文档”描述当时授权，不覆盖后续明确实现请求。
3. 文档、测试、代码冲突时，指出具体差异。测试证明当前行为，不自动决定产品规则；待审计建议也不自动成为实现授权。只对会改变功能、接口或数据处理的未决项提问，继续不受影响的部分。
4. 按症状选一个主要技能，定位后按需要读取相邻技能。跨类型问题沿实际数据与调用链调查，不一次加载全部技能。

## 实现与修复

- 修复先记录触发条件、预期和实际结果，建立能捕获原症状的验证方式。简单视觉问题可以使用运行截图和操作；状态、奖励、兼容问题优先使用可重复测试。
- 新功能先定义可观察的完成条件，再完成数据、逻辑、界面和必要持久化链路。配置字段以当前数据契约为准；契约尚不支持的需求需要明确实现支持。
- 用隔离存档和测试夹具验证。保留用户存档、稳定内容 ID 和工作区已有修改。发布、删除重要数据及其他外部操作遵循现有授权边界。
- 专项技能提供项目路径和不变量。普通排错直接执行；复杂、间歇或性能故障可使用当前环境中可用的 `diagnosing-bugs`，不依赖个人技能才能完成基本任务。

## 验证与交付

- 从 `package.json` 确认当前命令。逻辑、内容或集成修改运行相关测试和构建；纯说明或技能修改验证文件结构、链接、描述与选择边界，不为形式运行游戏测试。
- 视觉改动执行根目录规定的三个竖屏尺寸、交互和动态效果检查，交付实际运行截图。截图、模拟器与真机结果分别标明；构建成功不等于视觉或手感通过。
- 完整副本执行目标包的 ready 校验。既有原型的全量 ready 失败不能用来掩盖目标包缺失，也不要求无关修复补完所有历史包。
- 交付根因或实现结果、关键修改、实际运行的检查、剩余限制。保留可定位的必要截图和测量结果，移除临时探针；不自动建立流程报告或发布 GitHub 消息。
