# 存档、调查恢复与版本迁移

## 现行实现：两种成长规则与一次备份（2026-10-16）

仍使用schema 3与现有本地数据库，新增可选`research`和`run.rogue`字段。新档包含`research`；缺少此字段的旧档维持原永久经验规则。新规则的局内状态保存等级、剩余经验、技能、觉醒、精英机会、候选、随机种子、重选次数、自动技能冷却和持续符阵。升级选择、暂停、刷新都不重新随机或重发奖励。

新规则结算清空`run`，因此等级与技能不带入下一局。结算将已获得的研究能量、阶段冥币、装备和已拾取材料入库，失败同样保留。案件证据和Boss报告只在成功撤离时记录。结算后再次调用不会再发奖励。死亡不能通过同帧拾取经验复活。

旧档在返所后通过“升级→查看转换并确认”显式转换。预览列明：旧累计能量等额变为研究能量；旧等级属性结束生效；职业、案件、冥币保留；旧武器/护具升级映射对应新装备；已购买职业能力返还90冥币、4样本、2零件。进行中的旧调查必须先结束，不在半局中改变规则。

确认时在同一IndexedDB事务内写入转换后档案与首份`legacy-before-roguelite`备份。事务失败时不发布新内存状态。原备份不覆盖，可从研究台或设置页导出，再通过正常导入恢复。新旧档互相导入时完整替换字段，不能留下旧配置中的可选字段。普通存档导出与转换前备份导出分别提供。

## 1. 一份存档的数据

一个配置档含 `saveId`、存档schema、游戏规则版本、最后写入版本、设置、角色身份、当前/累计等级能量、基础职业、改职机会状态及全部分支解锁、基地等级、剧情报告标记、已领奖案件ID、任务进度、冥币材料、库存物品唯一ID、穿戴槽、神器部件与已组装神器、未结调查和确定性掉落状态。

当前调查另存：runId、所选Boss、战区随机种子、有效调查时间、玩家生命/位置/补给、已生效波和批次、下一批预警剩余时间、存活敌人及唯一ID、弹道/危险、临时物品清单、案件增量、Boss阶段与一次性结算标记。

永久档与临时调查分区。无负重和格数限制；不存派生的界面文案，装备属性由稳定模板ID重新计算。

启动读取存档后自动进入对应场景。无存档停留首页；有效存档恢复大厅、结算或暂停中的调查。调查恢复时保持暂停，直到玩家主动继续；加载和后台等待不推进调查时间。

## 2. 何时写入与防重

新档、升级、任务提交、买补给、穿戴/回收装备、转职、扩建、胜利、安全撤离和失败结果均作为原子操作写入：完整成功或状态保持原样。动作结果写入后才显示“已保存”。异常时暂停并允许重试，不额外消费金钱、材料或补给。

战斗内击杀增加能量和掉落使用稳定ID（runId+entityId+奖励槽），拾取只改变该ID状态；升波只按保存的时间和批次增加一次。Boss奖励、首次报告、神器第1/3/5次保障、案件奖励均有独立结算ID和已完成标记。

导入存档是整个档案替换，不与当前背包、能量或领奖标记合并。导入前显示等级、职业、地区、调查是否进行中和最后保存时间；确认前可取消。每次用户导入不覆盖原文件备份；失败保留当前数据。JSON导入做schema与数量范围验证，错误指出字段并拒绝部分写入。

本地优先使用IndexedDB异步事务。不支持时显示可下载导出与明确的浏览器限制；不能假装云端已保存。页面后台/手机锁屏时暂停战斗并尽快写恢复点；重新进入显示“继续调查”或“返回调查所”，不让离线时间推进波次。

## 3. 失败/胜利/撤离的资产矩阵

| 状态 | 保留 | 丢失或发放 |
| --- | --- | --- |
| 普通击杀 | 已吸收克苏鲁能量立即永久写入 | 自然装备、材料、证物、神器部件进入本局临时清单 |
| 安全提前撤离 | 等级、能量、穿戴和仓库永久物 | 只带回实际拾取临时物；未拾物与未撤离案件增量丢失；不发Boss胜利包 |
| Boss胜利 | 等级、能量与本局已击杀掉落 | 自动把所有已生成场内奖励汇集入本局胜利清单；残敌退散不给奖励；成功提交胜利返回后统一入库 |
| 死亡/放弃 | 历史等级/能量、穿戴、仓库、基地、已提交报告与职业分支 | 清空本局临时库存、本局新增证物和进度；保留已经逐击杀吸收的能量 |
| 存档写入失败 | 磁盘上最后一个完整状态 | 暂停模拟、显示重试；不宣告新升级/领奖成功，不重复扣款 |

Boss死亡即进入胜利冻结，不再受残敌伤害。若点击安全返回前关闭浏览器，读档恢复为已胜利且奖励待返所状态，不重新打Boss或重抽掉落。报告/任务/奖励事务一起写入后再标记已返所。

死亡与Boss同帧时按战斗规则结算；只有Boss被击败且玩家生命仍大于0才胜利。先扣除该批最高有效伤害、确定玩家生死，再确认Boss死亡，避免设备帧顺序决定物品保留。

## 4. 旧版档案迁移

旧v3库 `fog-harbor-investigator-v3` 与矿洞 `abyss-office` 保留只读源，不原位覆盖。新版建v4库；迁移执行复制并在确认后进入新档。迁移过程幂等，同一源档可重试，不重复奖励。

矿洞档只显示“旧版档案不能迁移成新世界进度”，仍可导出，不杜撰神话装备映射。

v3雾港档迁移：现有职业记为已选基础职业，角色初始等级设10、累计能量设1800；改职机会保留一次且30级前有效（明确显示“版本迁移补偿”，不是历史击杀）；职业基础枪标为已领取并补齐一次；强化武器/护具逐项折算为v4相近物品与等值冥币/材料，不双重保留25%旧升级加成；已提交案件、基地等级、资源、设置、Boss报告、已解锁地区和神器记录按原ID保留。旧库本身不修改。

旧进行中的调查不能静默套用新波次：迁移完成后将角色安全返回调查所，保存已安全入档的历史进度，丢弃旧局未撤离战利品，不增加Boss报告或新掉落保障计数；迁移预览明确显示这项损失并在确认前给出旧档导出。这个迁移是可撤销的复制，旧v3仍在，用户可以继续旧版档案。

迁移报告列出转换前后等级、货币材料、已交案件、装备、神器、基地与处理中的调查。数量越界、未知ID和损坏记录使迁移停止，保留源；不自动猜职业或把无效数据清零。

## 5. 本地设置与多档

首版一个当前活动档，支持完整JSON导出/导入与新建档确认，不做自动多槽同步。音乐/音效/减少动态效果按档保存；系统减少动态偏好和游戏设置任一要求减少时，关闭循环装饰动画，保留静态危险信息。设置不影响随机种子或奖励。

## 6. 验收

强制覆盖每个原子操作写入前后断开、重载可恢复调查、同一批次不重复刷怪、升级不丢能量、Boss胜利重开不重抽、不重复保障、不重复领奖、导入拒绝损坏且当前档未变化、重复迁移不复制奖励、旧源库未修改、v3运行中档案迁移预览与取消、存储空间不足/IndexedDB禁止。此文档定义目标，不代表上述新schema与迁移代码已实现。

### 当前v3海图报告兼容（2026-10-15）

本轮只新增可选`bossReports`数组，保存已成功带回的Boss报告ID；校验拒绝未知或重复ID。缺字段旧档仍可读取，视为无已记录报告，不凭旧`selectedBoss`推测击杀。进行中的旧调查可继续；新启程时校验地区顺序。报告与返所奖励一起通过现有事务保存，重载不重复记录。本节不是v4迁移实现。

### 当前v3经验兼容（2026-10-15）

本轮在现有schema3加入可选`energy`，缺字段按0计算，不追溯虚构旧击杀，也不执行v4迁移补偿。调查与结算可选`energyGained`记录本次能量。所有字段拒绝负数、非整数和非有限数。最大生命随等级与穿戴计算，保存不再把120作为固定上限。

经验与敌人死亡、掉落和波次一起写入现有完整状态事务。读档保留死亡状态，不重复发经验；退散残敌无经验。失败/放弃只清临时物资，保留已吸收能量。相同JSON导入为整档替换，不与现有经验叠加。
