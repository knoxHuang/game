# 数值与战斗节奏调优

先执行 [游戏技能共用约定](../../../docs/agents/game-workflow.md)。

## 建立基线

读取主题对应的战斗、职业、装备、副本和 [设计审计](../../../docs/design/design-audit.md)。先确认机制实际可用；尚未实现的系统可做计算分析，但明确不能代替运行测量。

## 调优流程

1. 明确目标体验和待验证假设。记录版本、配置、装备/职业、操作方式、随机样本和已有计时，保留可复测基线。
2. 选择能区分问题的指标：每波残敌/空窗、Boss 入场生命、伤害来源、通关时长、首次转职耗时、奖励每分钟收益、缺件与保底次数。性能指标用于判断设备负载，不代替难度指标。
3. 覆盖入门低输出、常规配置和较强配置。比较通关、提前撤离、失败与刷首波策略；校验奖励和风险是否鼓励预期玩法。
4. 区分机制问题与数值问题。选敌、不可躲伤害或丢奖励等缺陷先修复，避免通过加血/加奖励掩盖。每轮只调整能解释结果的一组参数，保留前后对照。
5. 概率与曲线用可重复计算和足够样本检查，说明样本量与局限。手机可读性、操作和职业差异用实际试玩检查；自动模拟不能证明人类手感。
6. 用户只要求评估时交付建议；明确要求调优时修改唯一数据源，运行相关校验/测试并复测。新公式、门槛和建议结果不自动升级为用户确认。

## 完成条件

给出基线、调整或建议、测量结果及剩余假设。未测的目标时长、通过率和设备表现标为未验证。
