# 游戏试玩与集成验收

先执行 [游戏技能共用约定](../../../docs/agents/game-workflow.md)。

## 选择验收范围

读取 [游戏总纲](../../../docs/design/game-design.md)、[界面设计](../../../docs/design/interface-design.md) 和本次完成条件。先核对实际实现，不把未授权草案加入必过项目。按 `package.json` 启动本地游戏。

## 执行检查

1. 从改动风险选场景：局部修改验证受影响链路；阶段交付覆盖新建/继续 → 接案或整备 → 出发 → 普通波/Boss → 成功、提前撤离或失败 → 返回提交与再次出发。
2. 使用隔离存档，保留初始状态和操作步骤。覆盖必要的空状态、资源不足、锁定、重复点击、暂停恢复、切后台、重载和存储失败；只测试与本轮范围相关的分支。
3. 视觉和输入检查三个规定竖屏尺寸。验证触摸区、正文、滚动、层级、热点对位、同时移动与动作、输入取消、预警和动态效果设置，并保留实际运行截图。
4. 大量残敌与 Boss 共存时，观察预警、安全路线、自动选敌与镜头。性能调查先记录设备/浏览器、视口、实体数和帧耗时基线，再定位 CPU、渲染、分配或刷新热点；必要时读取相关修复技能。
5. 自动测试、浏览器模拟与真机试玩分别记录。截图证明布局，持续运行记录支持性能结论，人工试玩支持手感判断；没有真机就说明限制。
6. 发现缺陷按所属技能处理后，重新跑失败场景和受影响链路。验收请求中对修复授权不明确时先交付问题与证据，不自动扩成大范围重构。

## 完成条件

按完成条件逐项给出通过、失败或未验证，附关键截图/数据及阻碍。交付验证结果不自动发布、部署或更新外部任务。
