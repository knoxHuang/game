# 游戏设计与阶段评估

先执行 [游戏技能共用约定](../../../docs/agents/game-workflow.md)。

## 资料与范围

先读 [游戏总纲](../../../docs/design/game-design.md)，再按主题读同目录战斗、副本、职业、装备、角色、界面与审计文档。只加载相关专项；现有规则归属以总纲索引为准。

## 评估流程

1. 确定本次要解决的玩家问题、已确认约束和交付类型。把现有实现、未决建议与用户新要求分开；文档状态冲突用代码和相关测试核对完成度。
2. 从玩家操作与反馈推演正常、失败和重复游玩路径。重点检查自动射击与走位决策、五波叠怪、首次转职、奖励回报、案件与自由调查的关系。
3. 比较满足目标的少量方案，说明体验收益、制作成本、跨系统影响和风险。单人手机游戏优先完成可试玩闭环；新系统必须解决具体问题。
4. 将结论分为确认要求、推荐方案和需试玩验证的假设。数值示例标为假设；只有用户明确确认才能升级为确认要求。
5. 用户要求保存设计时，编辑唯一负责该规则的专项文档，并同步必要索引/状态；普通讨论直接交付结论，不额外创建报告。要求实现时读取功能实现技能。

## 完成条件

给出推荐方案、关键取舍、未决问题和验证办法。设计讨论只交付设计，不改变代码、资产或外部任务。
