# 游戏功能实现

## 定义完成范围

读取 [共用约定](../../../docs/agents/game-workflow.md) 和相关专项设计。若任务来自 GitHub，按 `docs/agents/issue-tracker.md` 获取明确规格；不因实现功能自动创建或更新外部任务。

## 实现流程

1. 对照代码确认已完成和缺失部分，写出本次可观察的完成条件。明确当前授权覆盖哪些设计建议；会改变数据或功能的未决项集中提问，继续不受影响的部分。
2. 按需求追踪 `model.ts` 状态、`engine.ts`/`battle.ts` 行为、`main.ts` 调度、`view.ts`/`renderer.ts` 展示与 `storage.ts` 持久化。选择最小可维护改动；不为方便把不同状态的规则复制到界面。
3. 先贯通一个可运行流程，再补边界。配置能力需同步 schema、校验、读取与运行时消费者；持久字段需同步保存、恢复与旧存档策略。
4. 界面使用既有场景与材质，读取界面修复技能中的视觉约束；新图像读取美术制作技能；奖励链路与存档分别读取对应技能。只加载实际涉及的部分。
5. 为状态变化、奖励去重、失败回滚和兼容等关键风险添加适当测试，运行相关测试和构建。实际操作正常、失败和恢复流程；视觉变化交付三尺寸截图。
6. 同步本次确实改变的设计完成状态，区分已实现、已验证和未验证；保留无关草案。交付代码与证据，不以只有按钮、字段或占位资源代表功能完成。

## 完成条件

验收条件覆盖的数据、操作、反馈和持久化链路实际可用。若只完成部分，明确剩余工作及阻碍，不降低原交付标准。
