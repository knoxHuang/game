# 存档与恢复修复

先执行 [游戏技能共用约定](../../../docs/agents/game-workflow.md)。

## 调查入口

检查 `src/storage.ts` 的校验、解析和 SaveStore，`src/main.ts` 的 commit、自动保存、启动、导入导出与错误恢复；核对 `src/model.ts` 和 `src/battle.ts` 的恢复字段与兼容逻辑。

## 排查与修复

1. 使用存档副本或隔离浏览器存储，保留原始数据。记录版本、操作顺序、错误和内存/持久化差异；收集样本时去除无关私密信息。
2. 区分 JSON/语义校验失败、IndexedDB 打开/事务失败、异步写入顺序、状态发布时机和兼容转换缺陷。导出持久化存档与导出当前内存分别验证。
3. 比较保存前、实际落盘、重载后状态；检查自动保存快照、并发操作、事务失败和重试。若涉及 schema 或字段变化，明确兼容策略与拒绝损坏数据的行为。
4. 兼容转换保留可保留的生命、资源、案件与调查进度；转换和重载不重复生成奖励、波次或消耗。重大迁移语义缺失时先提出具体问题，继续安全准备。
5. 验证有效/非法输入、旧样本、重复恢复、保存失败再重试。解析往返用测试；IndexedDB、页面重载和切后台恢复需要浏览器验证。

## 完成条件

原缺陷不再出现，失败路径可恢复且原存档保留。清空数据库、新建存档覆盖和忽略校验不是默认修复手段；需要破坏性处理时遵循授权要求。
